# Tremolo

Amplitude modulation by a low-frequency oscillator:

```
edit_i = floor( orig_i * L(i) / 2^16 )
```

where `L(i)` in `[0, 2^16]` is a unipolar sine LFO sampled at position
`i`, from the 256-entry table generated by `scripts/gen_lfo_table.py` into
both `circuits/edits/tremolo/tremolo_table.circom` and `src/lfo_table.rs`.

## Naming

The reference implementation (`source_outputs/"pitch shifting 2.c"`) is
titled "pitch shifting", but its own comments describe, and its code
computes, a tremolo: `output = input * lfo` modulates amplitude, not
pitch. True pitch shifting needs resampling or a phase vocoder, neither
expressible at reasonable cost here. The circuit is named for what it
proves.

## The first edit needing a notion of time

Gain and attenuation are memoryless: `edit_i` depends only on `orig_i`.
Tremolo depends on the sample's absolute position, so the IVC state
carries a counter:

```
step_in  = [orig_hash, edit_hash, sample_index]
step_out = [orig_hash', edit_hash', sample_index + batch_size*comp_size]
```

The counter is proven, not supplied: each step advances it by exactly one
batch, and the verifier sees the final value, which must equal N. A prover
cannot shift the LFO phase to flatter the signal without breaking the
chain.

## Fixed point, and why no clamp is needed

`L` is an integer at scale `2^16`, so the post-multiply rescale is a right
shift by 16 rather than a general division — the same trick attenuation
uses, and the reason the scale is a power of two. Rounding is floor,
because bit truncation computes it natively; the off-circuit reference
must use `>>`, not `/`.

Since `L <= 2^16`, the product satisfies `|orig*L/2^16| <= |orig|`, so the
result is always representable at the source depth. Like attenuation and
unlike gain, no saturation logic is needed. Verified exhaustively against
the Rust reference.

## Normalized-space formulation

Samples arrive as `orig_n = orig + half`. The product `orig*L` is signed,
which the field cannot represent, so the circuit works with

```
u = orig_n * L + (2^16 - L) * half  =  orig*L + half*2^16  >=  0
```

from which `floor(u / 2^16) = floor(orig*L / 2^16) + half = edit_n`
exactly, with no correction term. Verified for every input at bit_depth 8
and 16 across the full range of `L`.

## Piecewise-constant LFO

`L` is looked up once per packed element (`comp_size` samples), not per
sample. A 256-entry lookup costs ~256 constraints, so a per-sample lookup
would make this circuit ~3x the cost of gain; amortizing over `comp_size`
brings it back in line.

The approximation is inaudible. At 44.1 kHz with `comp_size=15` the LFO
updates at 2940 Hz against a 5 Hz modulation (588x oversampled), and the
worst amplitude step between adjacent blocks is **0.046 dB** — well under
the ~1 dB difference limen. At `comp_size=31` (bit_depth 8) it is
**0.095 dB**. Report these figures rather than claiming the LFO is exact.
